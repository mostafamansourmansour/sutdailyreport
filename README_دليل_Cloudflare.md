# دليل رفع داشبورد القبول على Cloudflare Pages

الهدف: ترفع تقرير مرة واحدة، وأي حد يفتح اللينك يشوف نفس التقرير — على شبكة Cloudflare اللي بتفتح أوسع في مصر. مجاني بالكامل.

الرحلة ٣ مراحل. خد وقتك، وخلّص كل مرحلة قبل اللي بعدها.

## محتويات الحزمة
- `index.html` — الداشبورد نفسه.
- `functions/report.js` — الكود اللي بيخزّن التقرير ويوزّعه. **مهم:** اسم الفولدر لازم يفضل `functions` بالظبط.
- `wrangler.toml` — إعدادات المشروع.
- `README_دليل_Cloudflare.md` — الدليل ده.

⚠️ **نقطة مهمة جداً:** على Cloudflare، رفع الـ functions بالسحب والإفلات **مش شغّال**. عشان كده بنستخدم GitHub — دي الطريقة اللي بتخلّي الـ functions (المزامنة) تشتغل.

---

## المرحلة ١: ترفع الملفات على GitHub

### ١. اعمل repository جديد
- ادخل على github.com وأنت داخل بحسابك.
- فوق على اليمين، دوس على علامة **+** واختار **New repository**.
- في خانة "Repository name" اكتب اسم (مثلاً `sutdailyreport`).
- خليه **Public**.
- دوس **Create repository**.

### ٢. ارفع ملفات الحزمة
- في صفحة الـ repository الجديدة، دوس على **"uploading an existing file"** (أو Add file → Upload files).
- افك ضغط الحزمة على جهازك.
- اسحب **الملفات والفولدر** (`index.html` و`wrangler.toml` وفولدر `functions`) في صفحة الرفع.
  - مهم: فولدر `functions` لازم يترفع كامل جواه `report.js`. لو الرفع بالسحب مرفعش الفولدر، اعمل الملف يدوياً: دوس Add file → Create new file، واكتب في خانة الاسم `functions/report.js` (الشرطة `/` هتعمل الفولدر تلقائياً)، والصق محتوى الملف.
- تحت، دوس **Commit changes**.

بعد كده المفروض تشوف في الـ repository: `index.html`, `wrangler.toml`, وفولدر `functions`.

## المرحلة ٢: تربط GitHub بـ Cloudflare Pages

### ١. ادخل Cloudflare
- ادخل على dash.cloudflare.com (اعمل حساب مجاني لو ملكش).

### ٢. اعمل مشروع Pages
- من القايمة الشمال: **Workers & Pages**.
- دوس **Create** → اختار تبويب **Pages** → **Connect to Git**.
- أول مرة هيطلب منك تربط حساب GitHub — وافق واختار الـ repository اللي عملته (`sutdailyreport`).

### ٣. إعدادات البناء
- في صفحة الإعداد، سيبها زي ما هي (Cloudflare هيقرأ `wrangler.toml` لوحده).
- دوس **Save and Deploy**.
- استنى دقيقة، وهيطلعلك لينك المشروع (بينتهي بـ `.pages.dev`).

في المرحلة دي الموقع هيفتح، بس المزامنة لسه متشتغلش لأن الـ KV مش مربوط. نكمّل.

---

## المرحلة ٣: تعمل KV وتربطه + الباسورد

### ١. اعمل KV namespace
- في Cloudflare، من القايمة: **Storage & Databases → KV** (أو Workers & Pages → KV).
- دوس **Create a namespace**.
- اكتب أي اسم (مثلاً `reports`) ودوس Add.

### ٢. اربط الـ KV بالمشروع — **أهم خطوة**
- ارجع لمشروع الـ Pages بتاعك: **Workers & Pages → المشروع → Settings → Bindings**.
- دوس **Add** → **KV namespace**.
- في خانة اسم المتغير (Variable name) اكتب **بالظبط**:

  ```
  REPORTS_KV
  ```

  ⚠️ لازم بالحرف كده. الكود بيدوّر على الاسم ده تحديداً.
- تحت (KV namespace) اختار الـ namespace اللي عملته (`reports`).
- احفظ.

### ٣. اضبط الباسورد
- في نفس صفحة الإعدادات: **Settings → Variables and Secrets** (أو Environment variables).
- دوس Add، واعمل متغير:
  - **الاسم:** `UPLOAD_PASSWORD`
  - **القيمة:** الباسورد اللي هتستخدمه للرفع (مثلاً `SUT2026`).
- احفظ.

### ٤. اعمل Redeploy
- الربط بيشتغل بعد إعادة النشر. روح **Deployments** → دوس على آخر deployment → **Retry deployment** (أو اعمل أي تعديل بسيط على GitHub عشان يعيد البناء).

---

## إزاي تستخدمه بعد كده
1. افتح لينك المشروع (`...pages.dev`).
2. أول مرة بيفتح على بيانات عيّنة.
3. اضغط **UPLOAD** واختار ملف `.xlsm`.
4. أول مرة بس هيسألك الباسورد — اكتب اللي حطيته في `UPLOAD_PASSWORD`.
5. لو صح، التقرير هيتنشر، وأي حد يفتح اللينك هيشوفه.

**ملاحظة عن التوقيت:** التحديث ممكن ياخد لحد دقيقة يظهر لباقي الناس (طبيعي في KV).

---

## لو حصل أي مشكلة
- **الموقع بيفتح بس الرفع بيقول HTTP 404/500:** يبقى الـ KV مش مربوط صح. راجع المرحلة ٣، واتأكد إن اسم المتغير `REPORTS_KV` بالظبط، وإنك عملت redeploy بعد الربط.
- **"الباسورد غلط" وإنت متأكد:** اتأكد إنك ضبطت `UPLOAD_PASSWORD` وعملت redeploy بعده.
- **الموقع نفسه مش بيفتح:** جرّب من شبكة تانية. لو Cloudflare محجوب عندك، الحل الوحيد وقتها دومين خاص.

---

## الباسورد
محفوظ على السيرفر بس (في Variables) ومابيتبعتش للمتصفح. إنت بتديه يدوياً لللي معاه صلاحية الرفع. أي حد من غير الباسورد يتفرّج بس.
